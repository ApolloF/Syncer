# Safety fixes after the October 2026 review
Created: 2026-10-25 · Status: agreed

## Goal and non-goals
Goal: close the data-safety and trust gaps found in the October review and confirmed on the two test VMs, one PR per task, without changing what Syncer is for (saves follow you with zero clicks for known games). Done when every task's acceptance test passes, the check command and `wails build` pass, and the behaviour was seen once on the test VMs (Demeter 711/712, roll back to `clean` first).

Non-goals: the mods findings (personal build only; separate design), the first-run Google Drive copy and the hover-only row actions (UX round), the 1-2 min propagation lag of account changes between PCs (follow-up), Syncthing-level firewall help.

## Context
- A linked PC's folder list is applied without a click: `Reconcile` adopt loop `internal/meta/meta.go:208-257` → `Adoptable` (`:538-582`) → `AddFolderSpec` (`:854`). The only gates are the deny-list `internal/paths/paths.go:226-270`, `CheckSyncable` (`:290`), `InstalledOnly`, `Ignored`, `BackupOnly` and the Steam/OneDrive/Ubisoft skips. No manifest check: `discover.Classify` (`internal/discover/classify.go:143-187`) looks the label up but compares the path only for emulator folders. Peer folders that Syncer skips are listed under Games → Elsewhere → "On your other PCs" (`meta.Available`, `meta.go:750`; `folders.go:875-935`; `Games.svelte:851-875,1088`) with one action, "Sync here".
- Every linked PC is a Syncthing introducer (`internal/app/app.go:524-531`). A PC is "known" when it is in `store.State.SyncerPCs` **or** a `<id>.json` exists in the meta folder (`internal/meta/owners.go:54-66`); nothing ever deletes that file. `RemoveDevice` (`app.go:612-625`) removes the Syncthing device and forgets the PC locally, nothing else. Seen on the VMs: after A unlinked B, B still showed A "Online · In sync", kept A as introducer and kept sharing `syncer-meta`.
- Game hold: `holdSyncWith` (`internal/app/session.go:154-245`) pauses every folder on game start and resumes every id in `State.GamePaused` on exit; it never consults `accounts.OpFolders()` (`internal/accounts/ops.go:1232`), unlike `syncPause` (`internal/app/pause.go:168-189`). An account op records `WasPaused[id] = f.Paused` (`ops.go:307-337`), so a folder paused by the game hold is never resumed by the op, and the hold's resume can run between `swapHold` and `swapConfig` (`ops.go:846-965`).
- Backup target layout: `<target>\<id>\` mirror, `.versions\<id>\<stamp>` points (+ `.aside`, `.pinned`, `.origins`), `.syncer\<id>\<pc>.json` info and `.syncer\<id>\files\<pc>.json` file list (`internal/backup/info.go:24,89`, `files.go:50`). `Forget(target,id,true)` (`backup.go:597-620`) removes all three trees for every PC; the only "another PC backs this up" warning is frontend-side (`Games.svelte:1302`). `CopyHistory` copies, never moves (`backup.go:644`); split copies game→account, merge winner→game (`ops.go:527,1152`), `stopSync` old→`<id>--<pc>` (`folders.go:586-640,740`). Seen: four identical copies of every point after split+merge+delete.
- Walk: `.stignore` negation lines are dropped (`ignore.go:64`); a root that exists but can't be listed drops its error (`backup.go:264-270`) and the run writes an empty file list and reports OK; the retire step runs whenever `len(seen)>0` (`backup.go:357`) even after subfolder errors.
- `record` sets `State.LastBackup` for failed runs too (`background.go:271-277`); Overview and Backup page show `lastBackup.finished` as "Last backup" (`Overview.svelte:141`, `Backup.svelte:158`). `FolderBackups` is keyed by id and not carried over by `stopSync` (`background.go:283`, `details.go:30`).
- Updater: `decodeRelease` trusts the `digest` field of the same GitHub API response that names the asset (`internal/update/update.go:148-157`); no signature. `installUpdate` (`internal/app/update.go:136-199`) checks only the in-process `a.backingUp`, not `backup.Lock()` or `accounts.PendingOp()`. CI (`.github/workflows/build.yml:77-123`) publishes `Syncer.exe`, the installer, `SHA256SUMS.txt` and a provenance attestation; no secrets, no signing key.
- Cloud pull: `gatherPull` (`cloudpull.go:114-138`) checks Playing/Changed without a lock; `TakeFiles` (`files.go:198-285`) holds the backup lock, re-checks the *backup* files, swaps live files into `stage\old` and `RemoveAll`s it on success. `Snapshot` and `TakeFiles` take the lock in two windows.
- Conflicts: `conflict.Parse` reads the `.sync-conflict-…-<device>` suffix into `Device`, documented as "the PC that made the copy" (`internal/conflict/conflict.go:24`). Syncthing stamps that suffix with the **winning** change's modifiedBy; the copy holds the **losing** local content. `protect.go:148,163` label the copy with it; `FromDevice` (`conflict.go:194`) and "Use all from <PC>" group by it. Seen on the VMs: both cards said "from SYNCER-B" while the other version was A's own edit. `keeper` (`protect.go:291-314`) sends the loser to `.stversions` whenever `backup.Running()`.
- Syncthing is started with `--no-browser --no-restart` only (`internal/syncthing/manage.go:135`); the default `~\Sync` folder is created on first start.

## Decisions
- Peer folders are auto-added only when the label matches a manifest game **and** the path is one of that game's save locations on this PC — because a list of forbidden roots can never be complete, while the manifest is the thing that defines "a game save" for Syncer. Everything else (custom folders, unknown labels, size over `AutoAddMaxGB`) waits under "On your other PCs" with a visible count. Rejected: always ask (breaks the zero-click promise for the common case); bigger deny-list only (unbounded).
- Executable and script types are ignored in every save folder's `.stignore` and in the backup — defence in depth for the one-click path. Conservative list, no `.js`/`.reg` (some games keep them): `*.exe *.dll *.scr *.com *.msi *.bat *.cmd *.ps1 *.psm1 *.vbs *.vbe *.wsf *.wsh *.lnk *.hta *.cpl`. Mod folders (`Kind != ""`) are exempt.
- Syncthing's introducer is turned off; Syncer introduces PCs itself and every pair needs one Allow — because the Allow dialog is the trust boundary the docs promise, and introducer bypasses it. Rejected: keep introducer and only clean up on unlink (still trusts whatever a linked PC adds).
- A PC is trusted only through `State.SyncerPCs`; the presence of a meta file is no longer a trust signal. One-time migration keeps devices that already accept `syncer-meta` (they were user-linked under the old rule).
- Unlink is two-sided when the other PC is online: this PC publishes `unlinked: [id]` in its device file and waits up to 10 s for the meta folder to reach that PC before removing the device, so the other PC drops the link itself. If it is offline, the dialog says so and the other PC shows this PC as offline until unlinked there too. Rejected: detecting rejection on the other side (a refused connection looks like "off").
- "Also delete its backup and history" deletes the shared trees only when no other PC has an info file for that id; otherwise it drops only this PC's info and says which PC still backs the game up. Typed game name required, like the Elsewhere delete. Rejected: refusing while another PC's info is "recent" (stale PCs would block forever; the Elsewhere path handles those).
- Account ops own the pause state of their folders: the hold never pauses or resumes a folder in `accounts.OpFolders()`, and an op that finds a folder paused by the hold takes it over (`WasPaused=false`, removed from `GamePaused`). Rejected: making the op wait for the game (the switch happens because the player wants to play now).
- Releases are signed: CI signs `SHA256SUMS.txt` with an ed25519 key from the secret `RELEASE_SIGNING_KEY`; the app embeds the public key and installs only a `Syncer.exe` whose hash is in a validly signed sums file. Pure `crypto/ed25519`, no minisign/Sigstore dependency; signature file `SHA256SUMS.txt.sig` (base64). Rejected: in-app Sigstore verification (large dependency, GitHub trust roots); prompt-only (keeps a tampered asset installable by one click).
- The exe swap holds `backup.Lock()` and refuses while an account op is pending or locked.
- `TakeFiles` re-checks its preconditions under the lock right before the first rename and keeps the replaced files as a pinned restore point instead of deleting them.
- `.stignore` matching follows Syncthing: patterns in order, first match wins, `!` un-ignores. A walk that could not list the root or any subfolder fails the run; the retire step never runs after a walk error.
- "Last backup" means the last **successful** run; a failed attempt is shown as its own line. Before the first success the card says "No backup yet".
- Conflict copies are attributed by the copy's own Syncthing `modifiedBy` (the PC that renamed it, i.e. the loser side); the suffix device is shown nowhere. "Use all from <PC>" groups by that.
- History is linked, not copied: `CopyHistory` tries `os.Link` per file and falls back to copying (Drive streaming folders refuse links). Account history ids are labelled from the account name, never shown raw. `SyncerAccounts\.trash` entries older than 7 days are deleted at `Apply` (a restore point was saved before every swap).
- Cloud placeholders (`ModeIrregular`) fail a backup and refuse an account move with "make the folder available offline" — because silently skipping them would retire the mirror copies. Decided without a OneDrive reproduction; the message tells us if it fires.

## Architecture
No new packages. Changes stay inside the owning package; `internal/app` only wires.
- `internal/discover`: new exported `KnownLocation(label, path string) bool` (by-name lookup, `SameGame` normalisation, placeholder expansion **without** stat since the folder may not exist here yet; wildcards matched segment-wise). `internal/meta.Adoptable` gets a new skip `SkipAsk` ("ask") used when `KnownLocation` is false or `SizeGB > AutoAddMaxGB`; `Available` maps it to reason `ask`; `Reconcile` counts them into `State.Waiting` for the UI badge.
- `internal/meta` trust: `DeviceFile` gains `pcs []{id,name}` and `unlinked []id`. `Reconcile` turns a peer's `pcs` entries that are unknown here into `JoinRequests` with `via: <peer>`; `knownPCs` reads `SyncerPCs` only; `readOthers` ignores files of unknown devices; `RemoveDevice` publishes, waits, removes, deletes the file, unshares, reconciles.
- `internal/update`: `Release` gains `Sums *Asset, Sig *Asset`; `Verify(sums, sig []byte, pubKey) (map[name]sha256, error)`; `Download` requires a verified entry. `tools/release-sign` (stdlib) does `-keygen` and signing in CI.
- `internal/backup`: `Forget` gains an `others` check via `ReadInfos`; walk error handling; `TakeFiles(…, Precondition func() error)` and aside point for `stage\old`; `linkOrCopy` in `copyHistory`; `Matcher` rewrite; `Run` result `Attempted/Failed` split in `store.State` (`LastBackup` stays, UI reads `LastSuccess`).
- `internal/accounts`: `pause`/`resume` consult `store.State.GamePaused`; `.trash` sweep in `Apply`.
- `internal/app/session.go`: `holdSyncWith` skips `accounts.OpFolders()` both ways.

## UI
- Games → Elsewhere → "On your other PCs": rows with reason `ask` get the pill "Waiting for your OK" and an enabled "Sync here"; the Games nav item and the Overview show a count ("2 folders from SYNCER-B wait for your OK") reusing the existing notice component. Copy explains why: "Not a known save location on this PC."
- Devices: introduced PCs appear in the existing requests block ("SYNCER-C · linked to SYNCER-A", Allow/Ignore, full ID shown); Unlink dialog gains the offline sentence.
- Games → Remove dialog: ticking "Also delete its backup and history" reveals the typed-name field (same `label.confirm` as the delete dialog); Remove stays disabled until it matches; after the call the toast says either "Backup deleted" or "SYNCER-B still backs it up here, so the backup stays".
- Overview/Backup: "Last backup" from `LastSuccess`; a second muted line "Last attempt failed 2 h ago · <error>" when the latest run failed; "No backup yet" before the first success.
- Conflict dialog: "Current · from SYNCER-B" / "Other version · from this PC". No layout change. Minimum window 760×520 checked for the new pill and badge.

## Risks and open questions
- Manifest matching uses the label the peer chose; a user-added folder with a custom name will wait for a click on the other PCs. Accepted; the count badge makes it visible.
- Turning introducer off changes behaviour for existing three-PC setups: all pairs already exist in their configs, nothing is removed; only future PCs need the extra Allow.
- The unlink handshake needs the other PC online; offline case documented in the dialog.
- Signing key: a lost key means a new key embedded in a release signed by the old one. Note the procedure in `RELEASING.md`.
- Type ignores could hide a legitimate save file for an unknown game; the list excludes data-like extensions on purpose. Watch the issue tracker.
- `os.Link` on Google Drive for desktop folders: fallback copy, verified by the unit test's fallback path only.
- Open: none for the user; all four design choices were made on 2026-10-25.
